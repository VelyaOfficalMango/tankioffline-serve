# TANKI ONLINE — деплой на Amvera / Render / Koyeb

## Деплой на Amvera (рекомендуется)

1. Создайте проект на [amvera.ru](https://amvera.ru): тип сборки **Docker**
   (в репозитории уже лежит `amvera.yml` с готовой конфигурацией).
2. Загрузите репозиторий (git push в репозиторий Amvera или через интерфейс).
   Amvera соберёт Dockerfile сама: порт 8080, статика, звук, всё внутри.
3. В проекте откройте **Настройки → Переменные окружения** и добавьте:
   | Переменная | Значение | Зачем |
   |---|---|---|
   | `ADMIN_KEY` | длинный случайный ключ | доступ к `/admin.html` и `/api/admin/*` — **обязательно** |
   | `ALLOWED_ORIGINS` | `https://<имя-проекта>.amvera.io` | разрешить WS только с вашего домена |
   | `AUTH_PER_MIN` | `10` | лимит входов с одного IP (опционально) |
   | `RESTART_HOURS` | `6` | плановый перезапуск (опционально) |
4. Данные (аккаунты, баны, банворды, правила, чат-лог) пишутся в **`/data`** —
   это `persistenceMount` из `amvera.yml`, поэтому **сохраняются между
   перезапусками и редеплоями**. Раз в запуск сервер делает снимок предыдущих
   данных в `/data/backups/` (хранятся последние 5).
5. Игра: `https://<имя-проекта>.amvera.io` · Админка: `https://<имя-проекта>.amvera.io/admin.html`
6. Проверка живости: `GET /health` → `ok` (Amvera опрашивает сама).
7. Если сменили `ADMIN_KEY` в панели входа — новый ключ подхватывается после
   перезапуска проекта в интерфейсе Amvera.

## Модерация (встроена в сервер)

- **Страница блокировки** (`banned.html`, видна по `/banned` или при открытии игры
  с забаненного IP): красный бархат, нотация о нарушениях, **Причина**, таймер
  **«Осталось до разбана»** (навсегда = «никогда») и только два действия —
  «Удалить аккаунт» (самоудаление по сессии, `POST /api/delete_account`) и
  ссылка «Апелляция». Ссылку поменяйте в `banned.html` → константа `APPEAL_URL`.
  API страницы: `POST /api/baninfo` (по токену сессии → бан аккаунта, иначе → бан IP).

- **Мгновенный фильтр запрещённых слов**: каждое сообщение чата проверяется ДО
  доставки. Список слов живёт в `data/moderation.json`, при первом запуске сеются
  ЗАКРЕПЛЁННЫЕ слова (наркотики, преступления, мат — их нельзя удалить через
  панель, только добавить свои). Фильтр обходит транслит, замену букв цифрами
  (нapk0тики), пробелы между буквами и повторы (сссууука).
- **Действия слов**: `block` (блок+варн) / `censor` (замазать ***) /
  `mute` (блок+мут) / `ban` (блок+автобан на 24 ч). Настраиваются в панели.
- **Эскалация**: предупреждения копятся на аккаунте (сгорают через 48 ч по
  умолчанию): 3 варна → мут 30 мин, 5 → бан 24 ч, 8 → бан навсегда. Все пороги
  меняются в панели («Модерация чата → Настройки»).
- **Проверка ника**: регистрация и переименование с запрещённым словом в нике
  отклоняются.
- **Журналы**: чат-лог (кто, что, когда, действие фильтра) и журнал модерации
  (все авто- и админ-действия) — вкладки «Чат-лог» и «Журнал» в панели.
- **Правила сервера**: `RULES.md` + редактор в панели; игроки видят их по кнопке
  «ПРАВИЛА» в лобби (обновление приходит в игру мгновенно). Публичный API:
  `GET /api/rules`.

## Админ-панель (`/admin.html`) — вкладки

Обзор (статистика, рассылка, личные сообщения, быстрый бан/варн по имени) ·
Игроки онлайн (кик, убить, переместить, ЛС, варн, бан) · Аккаунты (поиск, бан,
мут, варны, кристаллы, переименование, удаление) · 🛡 Модерация чата (банворды +
тест фильтра + настройки эскалации) · Чат-лог · Журнал · Правила · Комнаты
(закрытие комнаты) · Баны · Новости.

## Что понадобится
- Аккаунт на [render.com](https://render.com) (или [koyeb.com](https://www.koyeb.com))
- Репозиторий GitHub с этими файлами (или деплой из Docker-образа)

## Способ 1: деплой из GitHub (рекомендуется)

1. Загрузите проект в репозиторий: `server.py`, `game.html`, `admin.html`,
   `config.json`, `Dockerfile`, `.dockerignore`, `sound/`.
2. На Render: **New → Web Service → Build and deploy from a Git repository** → выберите репозиторий.
   Render сам найдёт `Dockerfile` — сборка пройдёт автоматически (Python 3.12-slim, без зависимостей).
3. В настройках сервиса:
   - **Port**: `8080` (Render сам пробросит трафик, но порт должен совпадать)
   - **Health check path**: `/health`
4. **Environment variables** (обязательно!):
   | Переменная | Значение | Зачем |
   |---|---|---|
   | `ADMIN_KEY` | ваш секретный ключ | доступ к `/admin.html` и `/api/admin/*` (перекрывает config.json) |
   | `TRUST_PROXY` | `1` | брать реальный IP из X-Forwarded-For — уже стоит в Dockerfile, но лучше задать явно |

   Опционально: `AUTH_PER_MIN` (лимит входов с одного IP, по умолчанию 10/мин),
   `AUTH_GLOBAL_PER_MIN` (лимит на весь сервер, 120/мин), `MAX_CONN_PER_IP` (8).
5. **Deploy**. Через ~минуту сервер поднимется на `https://<имя-сервиса>.onrender.com`.

   На Koyeb всё то же самое: **Create App → GitHub** → Port `8080`, health check `/health`.

## Способ 2: Docker-образ вручную

```bash
docker build -t tanki .
docker run -p 8080:8080 -e ADMIN_KEY=ваш_ключ -e TRUST_PROXY=1 -v tanki_data:/data tanki
```
и загрузите образ в registry (Docker Hub / GHCR), затем Create Service → Docker image.

## Важно

- **Данные** (аккаунты/сессии/баны/модерация) пишутся в каталог из `DATA_DIR`
  (в Docker-сборке это `/data`; локально — `data/`). На бесплатных планах Render
  том эфемерный: при редеплое аккаунты сбрасываются. На Amvera `/data` постоянный.
- **Не коммитьте реальный ADMIN_KEY в публичный репозиторий** — задавайте его
  через Environment variables на хостинге.
- Клиент подключается по `wss://` автоматически (страница отдаётся самим сервером,
  отдельный домен не нужен).
- Проверка живости: `GET /health` → `ok`.

## Локальный запуск (Windows)

```
run.bat
```
run.bat задаёт ключ админ-панели `ADMIN_KEY=test`. Админ-панель:
http://127.0.0.1:8080/admin.html — вход с ключом `test` (или своим, если поменяли).

## Стресс-тест

```
python testbot.py DM 8.0
```
Бот заходит в комнату и ездит по кругу. Порт/хост берутся из переменных
окружения `PORT`/`TANKI_HOST` (по умолчанию 127.0.0.1:8080).
